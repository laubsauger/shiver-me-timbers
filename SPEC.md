# SPEC

## §G GOAL
Web pirate combat demo (SoT-class water/sky/ropes/destruction) @ WebGPU three.js TSL. Company showcase — visual bar high.

## §C CONSTRAINTS
- three.js `WebGPURenderer` + TSL only. WebGL path ⊥. No fallback code.
- Shaders in TSL nodes; raw WGSL only where TSL can't (FFT butterfly OK).
- Desktop Chrome/Edge/Safari-26. 60fps @ 1440p, Apple Silicon / discrete GPU ref.
- TypeScript + Vite. No game engine libs. Physics hand-rolled (buoyancy, projectile) — no ammo/rapier unless task says.
- Modular files: 1 system = 1 dir, file ≤ ~250 lines soft cap. Shader chunks own files.
- All tunables ∈ `params/*.ts` modules → Tweakpane debug panel. Magic constants in shaders ⊥.
- Sim deterministic & serializable (multiplayer later): fixed timestep, seeded RNG, sim state plain-data store.
- Ships procedural, destruction-first (modular pieces). Later AI-gen mesh swap ! keep same socket/piece contract.
- Heavy sims = compute passes (`Fn().compute()`), storage buffers/textures. Frag-shader ping-pong GPGPU ⊥.
- Ref doc: `docs/handoff.md` + PNGs. YouTube talk y9BOz2dFZzs = ground truth for look.

## §I INTERFACES
- app: `npm run dev` → Vite @ localhost, single page canvas.
- gate: no WebGPU → static "WebGPU required" page, zero crash.
- input: WASD/mouse sail+steer, camera orbit+follow, Space fire cannon, Tab debug panel.
- input/freecam: `C` toggles free↔follow. Free: WASD fly view-axes, R/F rise/descend, Shift fast ×12, Ctrl slow ×0.1, mouse look, wheel = travel speed. Free swallows WASD/R/F in capture phase (⊥ leak to rudder); keyup never swallowed; Q/E sail trim still live. Free ⊥ ship-relative → no snap-back by construction; dives to `freeMinY` −300m.
- debug: Tweakpane — ∀ params/* groups, weather presets (calm|swell|storm), perf HUD (fps, ms per pass).
- file: `src/params/*.ts` — one module per system, typed, hot-reload.
- state: `SimState` plain JSON-serializable object — ships, wind, time, seed, projectiles, damage.
- assets: `assets/` textures (foam crest/soft, flowmap noise, cloud distort cubemap, wood PBR). Procedural where possible.
- src layout: `src/core|ocean|foam|deckwater|flowfoam|clouds|ropes|ship|sea-physics|combat|ai|sky|params|debug|state|ui`.
- ui: DOM overlay (no canvas UI) — HUD, pause menu (Esc), settings. Settings persist localStorage.
- ui/settings/graphics: res scale, quality preset, AND per-feature toggles — reflections, caustics, deck water, spray, shadows(+map size), post FX, rain, island/palm density. Every expensive system ! individually switchable from the menu, not only Tweakpane.
- ui/settings/audio: master / music / sfx / ambience, each independently. Missing entirely today.
- ui/cinematic: fullscreen defaults to CINEMATIC — every debug overlay hidden (Tweakpane, perf HUD, dev readouts). `F1` toggles the dev layer back on/off. Photo mode hides the game HUD too, leaving only the rendered frame. Purpose: capture/recording (§T.39).
- ui/hud: apparent-wind indicator + sail-trim/reef readout (pairs w/ the flag telltales — see the wind, then answer it).
- audio/music: music bus + playlist engine — multiple tracks, shuffle/sequential, crossfade, per-track gain, ducking under combat. Tracks drop into `assets/audio/music/`.

V49: cross-owner aliasing: when material A multiplies its screen-differentiated height by a factor sampled from B's texture, the product rule hands the normal `H·dS/dx` — B's minification aliasing amplified by A's own magnitude. NEITHER owner can see it alone (A's field is fine; B's texture is fine; the bug lives in the PRODUCT), and it hides entirely while the factor is constant (dry deck ⇒ dS/dx = 0). ∀ factor scaling a differentiated height ! band-limited or read from a filtered tier by its OWN owner.
V44: ∀ value reaching an ADDITIVE light slot (`emissiveNode`, addLight…) ! provably ≥0 AND bounded AT SOURCE, not clamped after. Attenuation/occlusion ! expressed MULTIPLICATIVELY (less light arriving = a multiply), never as a negative addend. Corollary, learned the hard way: **flooring a divisor bounds the DIVISION, not the QUOTIENT** — `ray/max(y,ε)` is finite but can pin at 1/ε, and its finite difference then explodes. Clamp the magnitude of the RESULT too. Bounded factors ⊥ ⟹ bounded product.
V48: ∀ texture sampled under minification ! a mip chain (`generateMipmaps`, `LinearMipmapLinearFilter`) or an explicit filtered tier. Unmipped minified sampling = per-pixel aliasing, and it is WORSE when the sample feeds a screen-space-differentiated height (relief/normal) — the derivative of noise is louder noise. FOURTH occurrence: foam StorageTexture (no mips possible → reduction chain), ocean far-field, deck field, and mast staves — the last needs no texture at all, just `fract(atan2(z,x)·n)` going sub-pixel, which `reliefNormal` then differentiates into random normals and diffuse averages to BLACK. ∀ PROCEDURAL periodic term ! band-limited by `fwidth()` too, not only textures. Symptom is always "uniform per-pixel speckle over a whole surface", never a localised artifact. SIXTH occurrence + the refinement that finally killed it: band-limit ! be measured against the SHARPEST FEATURE's own width, ⊥ against the REPEAT. A 0.044m caulk seam inside a 0.55m plank goes sub-pixel 12× sooner than the plank does, so a `fwidth(plankCoord)`-vs-period gate (which fixed the masts, where feature≈period) left the whole hull+deck speckling over the entire distance band between the two. Cure = 2 halves, both required: (a) WIDEN — transition width ≥ 2 px of its own coord's fwidth, so the fn stops varying faster than the sample grid (1 px ⊥: neighbours still straddle the full step); (b) FADE amplitude ×feature/effective, = the average that pixel should have seen. (a) alone smears a 4cm groove over a whole plank at range; (b) alone leaves the step. Reaches 0 on its own once the repeat is sub-pixel ⟹ no separate period gate for EDGES; smooth per-period terms (crowns, per-board tone steps) keep the period gate. `src/ship/bandLimit.ts` + tests/shipDetail.test.ts "§V.48" block (CPU transliteration pair).

V50: a force that is physically an INTEGRAL over a body (∫ pressure·dA, hull heave = ∫ρg·h(z)·b(z)dz) ! be SAMPLED as one: ≥ 3 stations per shortest wavelength it must answer, weighted by the body's own section. N hand-placed probes ALIAS it — 8 probes over a 35 m hull summed to −0.28 where the integral is +0.10 at λ40 (WRONG SIGN: hull rose on crests) and to ≈0 at λ50, a null right through the sea's energy band (mean λ≈69 m). Fails SILENT and reads as feel, never as a crash: "doesn't react to the waves", "sinks into them", "not dynamic". ∀ such response ! verified as a SWEEP over wavelength, ⊥ one wavelength — the notch hides between samples, and a λ150 spot-check passes on the broken layout. Corollary: once the integral is real it does its own low-pass (a 35 m hull cancels an 8 m wave to 5%), so any Gaussian "footprint" smear stacked on top is either redundant or the thing eating the swell.
V51: ∀ SimState channel (each position/velocity component, the quaternion) = EXACTLY ONE integrator per tick. Other systems contribute FORCE/torque into the accumulator the owner integrates; they ⊥ run their own `x += v·dt`. A second integrator is silent — no error, no NaN, no drift, just a channel scaled by the number of writers (measured: ground speed exactly 2.000× velocity, so the ship outran her own wake, drag equilibrium and wave-encounter frequency at 26 kn of "13 m/s"). 3rd sighting of the two-owners shape after §B.6 (orientation) and grounding-vs-thrust; single-owner ! stated at the top of every module that writes shared state.
V52: ∀ coefficient that sets the response of MORE THAN ONE physically independent DOF ! be separately scalable per DOF. Heave, roll and pitch damping all came off one `buoyancyDamping`, so the (correct) decision to damp heave hard — the fix for "we're losing contact with the waves" — silently took roll to ζ 0.41, ~4× a real hull's, and the ship stopped rolling at all. Neither tuning pass can see the other's damage: each DOF looks defensible alone. Tell = a tuning note on one axis quoting a user report about a different axis. Damping ratios ! MEASURED per DOF (free decay → T and ζ), ⊥ inferred from the coefficient.

V53: ∀ hand-tuned physical constant (mass, inertia, stiffness, damping) ! carry a DIMENSIONLESS check against the real object, asserted in a test — ⊥ tuned by its effect alone. Every one of the galleon's numbers "worked" individually: roll period 7.1 s and pitch 4.1 s are both right for a 35 m ship. The ensemble was a 150 t model of a 600 t ship, because the periods had been bought by inflating the inertias around a mass 4× too small — pitch gyradius 0.73·L and roll 1.32·B against real 0.25·L / 0.40·B, and a heave period of 2.30 s against the closed form 2π√(d(1+a)/g) = 4.9 s. Reads as "feels a little bit too light", never as a wrong number. Checks that survive retuning: displacement vs ρ∇, stiffness vs ρg·A_wp, gyradius/L and /B, every natural period vs its own closed form.
V54: a lumped support/contact model ! give its sample points the BODY'S OWN EXTENT. Stations on the y=0 waterline plane with force = k·max(depth,0) make the hull an infinitely thin sheet: rise the whole equilibrium immersion (0.44 m) and support is not reduced, it is GONE, and the body is then ballistic at exactly −g with no water term at all — measured 15.4% of ticks and 1.87 s of continuous air in storm. Support ! fade over the real extent (zero buoyancy needs the KEEL clear, not the plane) AND ! stop growing past full submersion (bounded result, §V44). Tell = "it catches airtime / feels light" while the restoring force reads exactly −g for whole seconds. Corollary: giving the body extent RAISES the forcing everywhere (a station over a trough still makes torque, correctly), so the per-DOF damping (§V52) ! be re-measured after — roll went back to 180° capsize on the same coefficients.
V55: ∀ oscillator whose RATE can vary ! accumulate PHASE (`φ += ω·dt`, wrapped to [0,2π)). `time × rate` ⊥ — `t·ω(t)` is a valid phase only while ω is CONSTANT; the instantaneous frequency is `ω + t·dω/dt`, so ELAPSED TIME MULTIPLIES EVERY WOBBLE IN THE RATE, unbounded, and can drive it NEGATIVE (ripple reverses). Measured on the flags: 0.93Hz intended → 2.2Hz @15s, 5.8Hz @60s, 59.5Hz @600s, aliasing against the display past ~30Hz. Tell: LOOKS FINE ON A FRESH RELOAD, unbearable ten minutes in — survived three flag passes for exactly that reason. Wrap the accumulator (precision), and give a detuned harmonic its OWN accumulator: multiplying a wrapped value by a non-integer ratio breaks continuity at every wrap.
V56: the sea's OWN PIGMENT is a floor, not a base layer. ∀ term composited onto the water — sky reflection, Fresnel, foam, wake, spray, haze, glint, SSS — ! be judged by whether the water still reads as WATER at that view angle, distance and sea state. No single term may drive the surface toward neutral grey, and their SUM may not either even where each is individually defensible. Test the ratio that matters: sea chroma (or body-colour weight) sampled across view azimuth AND across distance, floored — not mean luminance, which a grey wash passes. FIVE separate complaints have been this one thing wearing different clothes: §B.12 cow pattern (sun-independent SSS), the teal hull (ambient desaturation in the wrong space), the rotation blowout (unbounded view-dependent lobe, 3.83x azimuth ratio), the grazing grey wash (`grazingSaturation` 0.55→0.15 under physical Fresnel — distant water is ENTIRELY grazing), and the wake reading as a white curtain instead of disturbed water. Each was fixed locally; none made the sea robust. A physically-correct term that erases the pigment is still a defect (§V.20 is a LOOK bar, not a physics bar).
V57: TSL mutators (`assign`, `addAssign`, `mulAssign`, `.toVar()`) are VALID ONLY INSIDE A LIVE `Fn()` BODY. `Node.prototype.assign` (three TSLCore.js) needs `currentStack`; with none it logs ONCE and RETURNS `this` UNCHANGED — the write is dropped and the graph still builds, compiles and renders. ⟹ ∀ node graph built at MODULE SCOPE or in a plain helper called outside `Fn()` silently loses every mutation. Measured: the ocean's whole §V.5 turbulent sub-noise (every `microDetail*` param) never reached a pixel, while the params read as tuned. Tell: `THREE.TSL: No stack defined for assign operation` at boot — it looks like noise and is the ONLY warning you get. Build slope/normal/colour graphs INSIDE the `Fn()` that consumes them, or return a value instead of mutating. Cf. §V.29 (`toReadOnly()` mutating a shared node) — same family: a TSL call that looks like it returns a new thing and does not.
V58: a DIRECTION-FREE metric cannot generate ORIENTED features. det J is AREA compression: its super-level sets are round and one-sized by construction, so foam injected from it needs a smear kernel to fake a shape — and a smear kernel with ONE global axis IS the shape (measured: cap axial spread 2.1°, length CV 0.08, every cap within ±2° of `windDirection+90°` across a 420m tile). Breaking is UNIAXIAL: use the minimum eigenvalue λ⁻ = ½(tr − √(tr²−4·det)) — Tessendorf 2004 eq.45-49, "the minimum eigenvalue is the actual signal of the onset of folding". a=−0.3,b=+0.3 ⟹ det J = 0.91 (compression and stretch CANCEL in the product) while λ⁻ = 0.70. λ± needs only trace + det, both already published, so the anisotropy moves to the INJECTION and the blur stays isotropic — shift-invariance and exact mass conservation KEPT, not traded (2.1°→21.4°, CV 0.08→0.68). GENERAL RULE: before adding a directional filter to make something look oriented, ask whether the SOURCE metric threw the direction away.
